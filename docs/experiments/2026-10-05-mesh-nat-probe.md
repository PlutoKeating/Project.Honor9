# 实验：Quetzal 分布式组网的 NAT 探测与 UDP 打洞

日期：2026-10-05

## 目的

Quetzal 1.0 要把同一个灵魂的多具身体连成全连接网状网，所有者要求公网服务器只用于建立第一次 P2P 连接、不持续中转。需要先确认：在荣耀9 的实际网络上，纯 Node 内置能力（`dgram`）能否完成打洞。设计稿见子模块 `docs/DISTRIBUTED.md`。

## 步骤

只读的网络测试，不改设备任何配置。脚本是零依赖的 Node 程序（未入库，内容见设计稿 §3.2 的描述），经 `scripts/deploy/lib.sh` 的 `dssh` / `dscp` 推到 Termux 主目录，跑完即删。

1. 同一个本地 UDP 端口依次向 `stun.cloudflare.com:3478`、`stun.miwifi.com:3478`、`stun.qq.com:3478`、`stun.l.google.com:19302` 发 STUN 绑定请求，比较映射端口（IPv4 与 IPv6 各一次）。主机侧做同样的测试。
2. 普通打洞：主机与手机各自取 STUN 映射，由人工交换端点，然后双方互发 20 秒。
3. 生日悖论打洞：手机开 256 个 UDP socket，每秒都向主机的映射端点发一次；主机向手机的公网 IPv4 撒随机端口（约 2000 个/秒），持续 25 秒。

## 结果

| 项 | 主机（家用宽带） | 荣耀9（当时 Wi-Fi 未连接，走蜂窝网络；Termux Node v24.18.0） |
|---|---|---|
| IPv4 映射 | 端点无关映射（EIM） | 对称 NAT（每个目的地址的映射端口都不同） |
| IPv6 | 没有可用的出口 | 公网 IPv6，端口保留；入站可达性待测（需要有 IPv6 的对端） |
| 可用的 STUN | Cloudflare、小米、Google | Cloudflare、Google（小米、腾讯的超时） |
| 普通打洞 | 0 包 | 0 包 |
| 生日悖论打洞 | 1.0 秒命中 | 0.8 秒命中，25 秒双向约 1.5 万包 |

结论：蜂窝网络下的荣耀9 可以用生日悖论打洞与 EIM 一侧直连。两部都走蜂窝的手机（双方都是对称 NAT）预计打不通，需要 IPv6 直连或经第三具身体转发；这一点等 P9 联网后再测。具体地址只在测试输出里出现过，没有写进任何文件。

## 回滚

无需回滚：没有改动设备，测试文件已从 Termux 删除。
