# 实验：时间墙重做、流式调用与工具执行回显

日期：2026-09-28

## 目的

控制台对话时出现 TLE。原因如下：

- 控制台对每次 RPC 设了固定的 90 秒绝对超时，基座有没有进展都不会重置它。
- 基座的模型调用是非流式的，每次固定 120 秒绝对超时。

结果是多步工具任务一定会超时。超时后后端其实还在继续运行，但界面上的回复丢了。

目标：

- 两道时间墙都改成按「无进展」计时。会话墙为 120 秒，模型调用墙为 90 秒。
- 由 agent 自己决定多轮节奏，基座不限制步数。
- 工具执行中、执行后都有单行回显。

## 改动（Project.Amani 1a14e9b、30e78c8）

- 运行时：
  - 四种协议改为 SSE 流式；每个数据块都会重置模型调用墙（90 秒）。
  - 新增会话（`mind/activity.ts`）：
    - 会话墙 120 秒。模型流的数据块、每一步开始、每个工具结束都会重置它；执行工具和排队期间暂停计时。
    - 每 15 秒发一次心跳。
  - 删除 `brain.maxSteps`，每一步开始前检查急停。
  - 通过 `activity` 事件广播进展。
  - 飞书对话在调用工具时回复一张实时更新的「执行过程」卡片。
- 控制台：
  - 对话等待改为「120 秒无进展」才超时。
  - 实时显示流式文字，每个工具一行卡片。
  - 超时或断线后，回复会自动补上。

## 部署

- `scripts/deploy/amani-release.sh`：运行基座测试 33/33 通过，发布 `20260928-085400-30e78c8`，健康检查通过。
- 控制台 `flutter build apk` 后用 `adb install -r` 安装。
- 构建环境问题：
  - pubspec 要求 Dart ≥3.13.4，本机 Flutter 过旧，执行了 `flutter upgrade`。
  - 升级后 Flutter 自带的 Gradle 插件（included build）与本机 `~/.gradle` 的镜像 init 脚本冲突（`FAIL_ON_PROJECT_REPOS`）。
  - 旧的 Gradle 缓存也导致 Kotlin DSL 编译失败。
  - 解决办法：改用临时的 `GRADLE_USER_HOME`（全新缓存，不带 init 脚本）构建。本机全局配置没有改动。

## 端到端验证

手机处于安全锁屏，无法用 adb 操作界面。改为在主机上通过 USB 转发连接手机网关的 WebSocket，使用与控制台相同的协议。发送的内容如下：

> 自检：请依次实际调用 shell（执行 uname -a 和 uptime）、recall（查询 荣耀9）、web_search（搜索 今天 天气）三个工具，每做一步先用一句话说明你在做什么，最后简短汇报每项是否可用。

模型：OpenCode Go / space-bunny-free。共 5 步，39026 tokens，全程 139.7 秒。

| 时刻 | 事件 |
|---|---|
| 7.1s | 第 1 步开始 |
| 13.8s | 叙述「先跑 shell…」；shell 执行中 → 完成，用时 0.2s，exit 0 |
| 14.0–112.1s | 第 2 步：模型持续流式输出约 98 秒。每 15 秒一次心跳，没有被任何时间墙中止 |
| 112.1s | recall「荣耀9」，没有命中 |
| 115.3s | 她自己决定换关键词再次 recall，命中了多身体共享日记 |
| 120.9s | web_search，用时 4.5s |
| 132.2s | 第 5 步给出不带工具的最终回复，`done` |
| 139.7s | RPC 返回（在 done 之后又完成了灵魂仓库推送） |

结论：

- 总时长超过 120 秒、单次调用接近 100 秒，只要有进展就不会被杀。
- 步数由模型自己决定：第二次 recall 是计划外自主加的一步。
- 20 批流式文字、每个工具执行中和执行后的事件都实时送达。
