# 实验：多会话、附件、后台恢复、工作中插话与 Azure 语音

日期：2026-09-28

## 目的

优化控制台的对话体验：
- 会话管理与找回；
- 多个会话同时进行，并且彼此可见；
- 附件，一次最多 20 个；
- 前端切到后台再回来时，进行中的卡片会丢失，需要修复；
- 她工作时可以插话、排队或打断；
- 可以随时停止的后台命令；
- Azure 语音工具与设置；
- 聊天自动滚到底部，以及「新消息」按钮。

## 改动（Project.Windler 83e83d9、28d17a4；本仓库适配器）

- **基座**：
  - 会话表；消息保存会话、执行过程、附件与插话方式；
  - 同一会话内按顺序处理，不同会话并行；每个会话的系统提示里包含其他会话的近况和正在进行的轮次；
  - 进行中轮次的快照；附件上传、多模态路由与 `read_document`；
  - 插话 / 打断 / 排队；shell 后台任务与 `shell_jobs`；
  - `voice_speak` / `voice_config`。
- **控制台**：
  - 会话列表；对话页以后端为准，随时重建；
  - 附件；发送按钮右侧的小三角；贴底与「新消息」按钮；语音设置页。
- **本仓库**：荣耀9 适配器实现 `playAudio`，使用 `termux-media-player`。

## 真机验证

在新建的测试会话里进行，没有打扰原来的对话；测试完成后已归档。

| 项目 | 结果 |
|---|---|
| 会话迁移 | 此前的 35 条对话归入「最初的对话」，打开时位于最底部 |
| 切到后台恢复 | 让她前台执行 `sleep 25`，第 10 秒切到桌面，12 秒后切回：进行中的 shell 卡片完整恢复并继续更新，这正是之前的问题 |
| 插话 | shell 执行期间补充一句，shell 结束后她看到并回答；消息下方标注「插话 · 在她工作时发送」 |
| 打断 | 她正在写 800 字长文时，通过小三角选择「打断」：输出立即中止，改为一句话回答；被截断的部分留在过程里 |
| 附件 | 分两次选择 2 张图片、1 个 docx、1 个 txt（4/20）：图片内容她都描述出来了（多模态），docx 用 `read_document` 读出，txt 内联；消息里显示缩略图和文件卡片 |
| 跨客户端同步 | 另一个客户端往同一个会话发消息，页面实时出现；上滑时「新消息」按钮变亮，点一下回到底部 |
| 会话管理 | 新建、自动标题、列表、归档、找回都正常 |
| 语音 | 设置页正常；适配器用 `termux-media-player` 播放本地合成的 wav 成功。还没有填 Azure 密钥，真实合成待配置后验证（请求格式已由模拟端点的单元测试覆盖） |

**测试**：运行时 59/59 通过（新增会话 9 个、文档 6 个、语音 5 个）；`flutter analyze` 无问题，`flutter test` 通过。

## 问题与修复

- **回复显示两遍**：「done」后取快照时，这一轮还没被移除。后端改为 done/error 时立即移除快照，前端也忽略已结束的轮次。
- **插话后第一段回复被覆盖**：改为作为中间叙述保留在执行过程里。
- **打开时没有完全到底**：Markdown 渲染完成后内容高度又增加了。改为用户在底部时，内容高度变化就贴底。
- **贴底后无法上滑**：贴底逻辑和拖动冲突。改为只在内容高度变化时才贴底。
- **file_picker 13 的 API 变化**：`FilePicker.pickFiles()` 改为静态方法，返回列表；每个文件改用 `length()` 和 `readAsByteStream()`。
- 顺带清理：共享存储「下载」目录里遗留的 `amani-bootstrap`（初次引导时留下的旧名目录）。

## 注意

- 重新发布基座会中断进行中的对话。部署期间你在「最初的对话」里发的「…音色太尖锐了，再调整一下～」因此没有得到回复，需要重发。之后每次发布前，我都会先确认没有进行中的轮次。
- 今天的 token 用量（约 300 万）已经超过每日预算 200 万，所以她自主醒来的频率被压到了很低（首页曾显示「抑制：预算用尽」）。需要的话在控制台「预算」里调高。

## 回滚

- 基座：`scripts/deploy/windler-release.sh rollback`。旧版运行时会忽略 messages 表的新列和 sessions 表。
- 控制台：安装上一版 APK。
