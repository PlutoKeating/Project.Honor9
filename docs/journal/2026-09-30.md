## 她对自己上一轮"失忆"：上下文缺了过程记录与时间

- 现象（飞书里装 Agent Mail CLI 的对话）：她先说「刚才那两张截图我都看过了」（实际只有一张），下一轮又说「我一次 view_image 都没调过」（实际调过两次），还把几小时前的截图当成刚发的，最后查审计表才撤回。
- 根因不在记忆文件，在对话上下文的结构（`Project.Windler/runtime/src/mind/brain.ts` 的 `history()`）：
  - 每一轮结束后，进入下一轮的只有双方消息的**最终文字**。工具调用、结果、中途说的话都存在 `messages.process`，但只给界面用，从不送回模型。她对自己上一轮做过什么没有任何记录，只能凭印象，于是一会儿多说、一会儿又为了"诚实"而过度否认。
  - 历史消息**没有时间戳**，分不清"刚刚"和"之前"。
  - 随消息附带的图片与 `view_image` 不去重：同一张图在上下文里出现两次，她就数成"两张"。
- 修法（Windler 提交 a5b903f、9b4b546）：
  - 会话历史每条带时间，插话 / 打断有标记；她的每条回复前附上那一轮的过程记录（最近 3 轮每一步，更早只给工具计数），预算 16000 字。
  - 同一轮内已在上下文里的图片（随消息附带或看过）记在会话的 `seen` 里，再 `view_image` 只提示"就是同一张"。
  - 新增内置工具 `recent_actions`：按小时、工具名查审计，用来核实自己"做没做过"。
  - 系统提示的「处境」里说明这条边界：记录里有的不否认，没有的不假装看过，不确定就查。
  - 测试：`runtime/test/context.test.ts`，全套 77 项通过。
- 顺带发现：她在 Termux 里跑 `ps` 看到"没有 node 进程"就断言"没有后台进程"——她自己就跑在 node 里。这是探针输出不可靠的问题，与上下文无关，未处理。
