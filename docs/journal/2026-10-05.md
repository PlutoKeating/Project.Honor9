## Quetzal：同步服务 sync/ 与触碰即同步（所有者第二轮拍板）

- 所有者拍板：GitHub 登录；会合、目录、信令全部放在所有者自己的服务器上；两边打不通时由服务器直接中转；服务对所有人开放；新增与仓库其他部分解耦的 `sync/` 模块，在服务器上 clone 后 `cd sync && ./start.sh` 一行跑起来。中途补充要求：安全第一，充分调研，不重复造轮子，用现代最佳实践。
- 据此推翻了自研打洞的方案：身体之间改用 WebRTC（`node-datachannel`，libdatachannel 绑定，有 android-arm64 预编译包），中转用 coturn。在荣耀9（Termux，蜂窝网络）上实测：`npm install node-datachannel` 直接装上，同一进程两端建立加密数据通道 196 ms，反复建立 / 关闭无泄漏。注意不要在原生回调里直接 `process.exit()`（触发 bionic 的 free 检查而崩溃）。
- `sync/`：Hono + ws + arctic + zod + node:sqlite，Caddy 自动 HTTPS，coturn 按 Enable Security 的加固清单配置（禁止中转到私有地址、有时效 HMAC 凭据、关闭放大相关特性）。自查发现并修掉两个安全 / 部署问题：agent id 全局唯一会被别人抢占（改为按账户隔离）；coturn 不指定中转地址会把 Docker 网桥当成中转地址（start.sh 改为探测主网卡并写 relay-ip / external-ip）。本机整套部署验证：HTTPS、信令、直连 194 ms、强制 TURN 中转 302 ms、伪造凭据被拒；15 项端到端测试。
- 触碰即同步：每次工具调用后 git status，有变化立即提交、3 秒去抖推送；网络类失败静默重试约 4 分钟，仍失败则以「基座提醒」插话进碰过记忆的那一轮；两边都改过的文件另存 `.incoming.md` 副本交给她裁决；灵魂仓库规范升 v8。runtime 136 项测试、bridge 12 项、官网构建均通过。
