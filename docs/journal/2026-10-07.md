## Quetzal 1.3：提醒、对话检索、时间换算

- 子模块新增 `reminder` 工具（一次性或 cron 重复，到点由基座准时发出）、对话进入 recall 的 FTS5 索引（可按时间段检索）、系统提示里的小日历。调研了 OpenClaw、Hermes、Letta、ChatGPT Tasks 的做法与 croner、chrono-node 等组件。
- 所有者提出参考独立项目 J-nify（等待合适时机提醒的秘书），并设想 Quetzal 与 J-nify 可各自独立使用、搭配时数据互通；已开子 agent 调研。
- 1.3.0 发布：提醒（准点与软提醒）、聊天记录检索、小日历、Linux 桌面版本机免配对码修复（所有者发现的问题）。1.3.1：混合版本时提醒也会响。荣耀9 与主机升到 1.3.1，真机端到端测试通过。
- J-nify 调研：第 0 阶段（软提醒、为什么是现在、小下一步、推迟）已做进 Quetzal；打通两个产品的后续阶段等所有者拍板。

## 统一账号：所有服务改用 PlutoKeating 账号登录

- 统一账号服务用现成的开源身份服务搭在所有者的另一台服务器上（运维细节记在私有仓库，不进本仓库）；发信用所有者注册的 yeah.net 邮箱的 SMTP。
- Quetzal 1.4.0：同步服务的登录从 GitHub OAuth 改为 OpenID Connect，账户按身份服务的 sub 区分；GitHub App 只用于建灵魂仓库与加部署密钥。生产库部署前做了备份。唯一的老账户（1 个 agent、5 具身体）一度被误接到运营者的发信邮箱对应的账号上，已撤回；等所有者用自己的 GitHub 或自用邮箱注册账号后再对接。已绑定的设备不受影响。官网同步上线。
- 待办：所有者在 GitHub 上删掉旧的 OAuth App，并从官网 Worker 的换令牌中转放行列表里去掉它；J-nify 的数据库选型（Cloudflare D1 或自建 Postgres）等所有者拍板后再迁移登录与数据。
- 所有者看过账号服务自带的登录页后否决了它。账号服务改成「只提供能力、不带界面」的开源方案，登录、注册、账号设置、授权确认、设备码的界面自己写，视觉沿用所有者主页的设计系统；验证码邮件也改成中文、同一风格。没有密码：邮箱验证码、通行密钥、GitHub 三选一，第一次用自动建账号。已上线，线上发信实测进收件箱；同步服务已切到新的身份服务。
- 所有者用自己的 GitHub 注册了账号；核对新账号关联的 GitHub 编号与同步服务里老账户的一致后，把老账户（1 个 agent、5 具身体）接到新账号上，同步服务的管理员改为所有者的个人邮箱。运营邮箱只用来发信。
